# 자주 빠지는 함정

SEED → shadcn 이식에서 실제로 걸린 것들이다. 증상으로 찾는다.

## CSS · Tailwind

| 증상                                                                                                                       | 원인                                                                                                             | 해결                                                                                                                                                                                                              |
| -------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 버튼에 테두리 · 회색 바탕 · 여백이 생긴다, 글꼴이 다르다                                                                   | Tailwind preflight 를 끈 채 쓴다(기존 화면을 지키려고)                                                           | 부품이 바탕값을 직접 적는다: `border-solid`(테두리 쓸 때) · `border-none` · `box-border` · `m-0` · `p-0` · `font-[inherit]` · `bg-transparent`. 원본이 글꼴을 안 정한 버튼(브라우저 기본 글꼴)은 그것도 같게 둔다 |
| `cn('text-t4', 'text-fg-neutral')` 에서 하나가 사라진다                                                                    | tailwind-merge 가 모르는 눈금을 같은 그룹으로 본다                                                               | 눈금을 `src/lib/utils.ts` 의 `createCn` 에 등록(spacing · text · leading · radius · shadow · ease, duration 은 classGroups)                                                                                       |
| 글꼴이 안 바뀐다 — `cn('font-[inherit] font-medium')` · `cn("font-['X',sans-serif] font-regular")` 에서 앞의 것이 사라진다 | tailwind-merge 가 `font-[…]` 임의 값을 굵기로 보고 뒤의 굵기 클래스와 겹친다고 지운다(Tailwind 는 글꼴로 만든다) | 값에 종류를 붙인다: `font-[family-name:inherit]`. 자주 쓰는 글꼴은 토큰(`--font-wordmark` → `font-wordmark`)으로 만들고 `classGroups` 의 `font-family` 에 등록                                                    |
| 상태 클래스가 기본 클래스를 못 이긴다(또는 반대)                                                                           | `@custom-variant data-open (&:where(…))` 처럼 `:where()` 는 특이도 0 — 순서로만 갈린다                           | 같은 속성을 두 클래스로 다투게 하지 말고 한 식으로 합친다(`opacity-[calc(1-max(var(--a,0),var(--b,0)))]`). 반드시 이겨야 하면 `data-[x]:` 속성 variant(특이도 있음)                                               |
| 원본 클래스를 덮던 소비자 CSS 가 안 먹는다 / 빌드하자 바뀐다                                                               | 번들러가 CSS 를 묶는 순서가 바뀌었다(CRA → Vite)                                                                 | 소비자 전용 CSS 를 맨 뒤에 import 하도록 명시. Tailwind 클래스는 `@layer utilities` 안이라 레이어 밖의 소비자 CSS 가 늘 이긴다 — 이 관계를 유지한다                                                               |
| 빌드 결과에서 특정 선택자가 사라졌다(`body:has(.x)`)                                                                       | 기본 CSS 압축기(Lightning CSS)가 떨어뜨렸다                                                                      | `build.cssMinify: 'esbuild'`                                                                                                                                                                                      |
| 원본 탭 밑줄과 반 픽셀 어긋난다                                                                                            | 원본은 정수 `offsetLeft` 로 자리를 잡는다                                                                        | 새 부품도 `round()` 로 맞춘다(원본 쪽을 따른다)                                                                                                                                                                   |

## 그림 대조

| 증상                                                           | 원인                                                                                              | 해결                                                                                                                   |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 창 · 시트를 열면 둥근 모서리 가장자리 수십 픽셀이 1/255 다르다 | Base UI 가 body 에 초점 지킴이 · 뒤 배경 막을 더해 Chrome 이 층을 나눈다. 끌 수 있는 prop 이 없다 | 갤러리는 `WithoutHelperLayers` 로 치우고 견준다. 실제 화면은 정책으로(이 레포: 그 그림만 까닭을 적고 기준을 다시 뜬다) |
| 같은 칸을 두 번 찍어도 그림이 다르다                           | 자리 · 래스터 시점에 따라 가장자리 픽셀이 달라진다                                                | 같은 자리에 번갈아 찍기, 여러 장 찍어 교집합, 열린 부품은 `Settled`                                                    |
| 휠 · 스크롤 부품이 칸마다 엉뚱한 값으로 보인다                 | `display: none` 이 스크롤 위치를 지운다                                                           | 칸마다 `page` 로 따로 연다                                                                                             |

## Base UI 동작

| 증상                                                        | 원인                                                                                                                         | 해결                                                                                                                                                                                             |
| ----------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 원본보다 많이 끌어야 닫힌다(시트 · 패널)                    | Drawer 의 닫기 기준이 상수(크기의 50% · 0.5px/ms)                                                                            | 끌기는 Drawer 에 맡기고 놓는 순간만 덧댄다 — capture 단계에서 `--drawer-swipe-movement-*` 를 읽고, Drawer 가 처리한 뒤 원본 기준이면 `actionsRef.current.close()`(`use-drawer-swipe-release.ts`) |
| 누르는 순간 메뉴 · 셀렉트가 열린다(원본은 뗄 때)            | Menu · Select 가 mousedown 으로 연다(누른 채 끌어 고르기용). prop 없음                                                       | 트리거의 `onPointerDown` · `onMouseDown` 에서 `event.preventBaseUIHandler()` — 뗄 때의 click 으로 연다(`open-on-release.ts`). 끌어 고르기는 없어진다                                             |
| 팝오버를 다시 열면 안쪽 상태(달력의 달)가 처음으로 돌아간다 | Base UI 는 닫으면 내용을 뗀다(원본은 한 번 열린 뒤 남겨 둔다)                                                                | 상태를 바깥(소비자)에 둔다. 또는 `keepMounted` 를 검토                                                                                                                                           |
| 탭 · 아코디언을 오가면 입력하던 값이 사라진다               | 안 보이는 패널을 그리지 않는다(원본은 숨겨 둔다)                                                                             | 소비자 화면에서 확인, 필요하면 `keepMounted`                                                                                                                                                     |
| `pressed:` 스타일이 고른 탭에 늘 걸린다                     | Base UI 의 `data-active` 는 '고른 탭'이라는 뜻 — 원본의 '누르는 중'과 이름이 겹친다                                          | 그 부품은 `data-active` 를 떼고 `aria-selected:` 로 고른다                                                                                                                                       |
| 폼 안의 버튼이 더는 제출하지 않는다                         | Base UI 의 버튼은 `type="button"` 이 기본(원본은 안 적어 submit)                                                             | 소비자에서 제출 버튼에 `type="submit"`                                                                                                                                                           |
| 내가 단 핸들러가 Base UI 보다 먼저/나중에 불린다            | `mergeProps` 는 오른쪽 핸들러를 먼저 부른다 — 부품마다 바깥 props 가 왼쪽일 때도(Drawer.Viewport) 오른쪽일 때도(트리거) 있다 | 부품의 소스에서 props 배열 순서를 확인한다. 먼저 읽어야 하면 `onXxxCapture`                                                                                                                      |
| 손으로 돌려도 기본값으로 돌아간다                           | `value` 만 주고 `onValueChange` 가 없다 — controlled 는 바깥 값을 따른다(원본은 화면 위치만 바꾸고 남기도 한다)              | 정상 동작. 갤러리에서 만져 볼 칸은 `defaultValue` 나 상태를 단다                                                                                                                                 |
| 터치로 끌면 손가락보다 덜 따라온다                          | 브라우저의 터치 슬롭 + Base UI 가 첫 움직임 자리를 기준으로 다시 잡는다(10~15px)                                             | 받아들이고 기록. 기준도 보이는 거리로 잰다                                                                                                                                                       |

## 이벤트 · 렌더 타이밍

| 증상                                              | 원인                                                                                                                 | 해결                                                                                                                                      |
| ------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 되돌아가는 transition 을 걸었는데 순간이동한다    | 핸들러 안에서 `offsetWidth` 같은 레이아웃을 읽어 스타일이 그 자리에서 확정됐다 — 그 뒤에 붙인 transition 속성은 늦다 | 읽기는 Base UI 가 처리하기 전(capture)에, 쓰기(속성 · 변수)는 나중에. 핸들러 안에서 읽기와 쓰기를 섞지 않는다                             |
| 끌어서 닫을 때 놓은 자리에서 위로 튀었다가 나간다 | Base UI 가 놓는 순간 인라인 transform 을 뗀다                                                                        | 놓은 자리를 CSS 변수로 남기고 `data-closed:[transform:translate3d(0,var(--x,0px),0)]` — 나가는 keyframes 는 `to` 만 두어 그 자리에서 시작 |
| 들어오는 움직임이 다시 돈다                       | 원본은 들어온 뒤 animation-name 을 뗀다                                                                              | 원본처럼 열린 뒤 일정 시간이 지나면 `data-animation-done` 을 붙이고 그 동안에만 animation-name 을 건다                                    |

## 원본 쪽 문제

원본에도 버그가 있다(이 레포에서 본 것: ProgressCircle 이 `minValue` · `maxValue` 를 잃음, 이름 없는 Checkbox 가 8px 넓음, 글자 수가 넘쳤을 때가 아니라 `invalid` 일 때 빨개짐,
두 달 달력에서 초점이 엉뚱한 버튼으로 감). 따라 할지 고칠지 정하고, 고치면 갤러리 칸을 빼거나 `known` 으로 두고 진행 문서에 적는다.
